# andrievskii.site

Персональный портал: Python 3.12 + FastAPI, серверный рендер Jinja2, Tailwind 4.
Без сайтостроительного фреймворка и без SPA. Node в проекте не появляется.

## Сборка стилей

Настройка Tailwind живёт в CSS (`static/css/input.css`), конфигурации в JS нет —
в четвёртой версии она не нужна. Собранный `static/css/site.css` лежит в
репозитории и подключён в `templates/base.html`.

```
bin\tailwindcss-windows-x64.exe -i static/css/input.css -o static/css/site.css --minify
```

Пересобирать после правки `input.css` или классов в `templates/`. Во время
работы над оформлением удобнее с `--watch` вместо `--minify`.

Исполняемый файл `bin/tailwindcss-windows-x64.exe` скачивается вручную,
в репозиторий не входит — см. `bin/README.md`.

## Запуск

```
.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

## Что где лежит

| Путь | Что внутри |
|---|---|
| `app/main.py` | приложение, маршруты, один обработчик раздела |
| `app/content.py` | чтение markdown, фронтматтер, проверка схемы работы |
| `templates/` | Jinja2: `base.html` и по шаблону на тип страницы |
| `content/ru\|uk\|en/` | тексты разделов |
| `content/works/{lang}/` | по одному файлу на работу, ru — базовый язык |
| `static/css/input.css` | исходный CSS: `@theme` с цветами и шрифтами |
| `static/css/site.css` | собранный Tailwind, в репозитории |
| `static/fonts/` | Golos Text, Literata, JetBrains Mono — woff2, локально |
| `app/leads.py` | заявка: запись в SQLite и сообщение в телеграм |
| `data/site.db` | база заявок (таблица `leads`), создаётся при первой заявке |

Текстов в шаблонах нет: любая строка, которую видно на странице, живёт
в `content/`. Правила проекта — в `CLAUDE.md`, структура разделов — в `BRIEF.md`.

## Правила оформления

- колонка текста — не шире 72 символов;
- один акцентный цвет на весь сайт (`--color-accent`);
- ни одной тени, скруглений больше 2px нет;
- тёмная тема — только через `prefers-color-scheme`, переключателя нет;
- на экране ровно одно основное действие: раздел объявляет его полями
  `action` и `action_to` во фронтматтере, поле одно, а не список.

## Языковые версии

Три языка, адреса — папками: русский без префикса, `/uk/`, `/en/`. Ни поддоменов,
ни параметров. Русский — язык по умолчанию.

Переводим не всё. Набор языковых версий задаётся содержимым `content/`:
есть файл `content/{lang}/{раздел}.md` — есть версия, нет файла — нет версии.
Списка переведённых разделов в коде нет.

Из этого следует остальное:

- в `<head>` — `rel="alternate"` на каждую существующую версию страницы,
  включая её саму, плюс `x-default` на русскую. Адреса абсолютные: домен
  из `SITE_ORIGIN`, а без переменной — из самого запроса. Версия одна —
  блока нет вовсе;
- переключатель языка в шапке — обычные ссылки, без JavaScript, и ведут они
  на ту же страницу, а не на главную. Версии нет — пункт остаётся тихой
  надписью без ссылки;
- запрос страницы, которой на этом языке нет (`/uk/archive`,
  `/en/works/fibi`), — 302 на русский адрес. Пустая страница не собирается;
- раздел без перевода не исчезает из меню чужого языка: пункт ведёт
  на русскую версию и помечен `lang` и `hreflang` — «Архив» иначе
  недостижим с украинских и английских страниц.

Сейчас без перевода один раздел: «Архив» (ролики и резюме — только
по-русски). Разделы и работы переведены на все три языка.

## Форма на «Контакте»

Три поля: задача (многострочное), срок, контакт. Больше полей не добавляется —
каждое лишнее поле стоит ответов. Подписи полей, кнопка и оба сообщения описаны
блоком `form` во фронтматтере `content/{lang}/contact.md`, в шаблоне их нет.
Рядом с формой — тихие ссылки из блока `links`: почта и канал.

Отправка — обычный POST на тот же адрес, без JavaScript. Тегов `<script>`
на странице нет ни одного. После успешной отправки — 303 на отдельную страницу
«спасибо» (`/thanks`, `/uk/thanks`, `/en/thanks`), а не сообщение на месте:
на переход ставится цель в аналитике.

### Куда попадает заявка

1. Строка в SQLite: `data/site.db`, таблица `leads` — `id`, `task`, `deadline`,
   `contact`, `created_at` (UTC), `lang` (язык страницы), `referrer` (источник
   перехода). Файл и таблица создаются при первой заявке.
2. Сообщение в телеграм — фоном, уже после ответа человеку.

Порядок односторонний: база рядом, телеграм за сетью. **Заявку нельзя потерять
из-за упавшего бота** — сначала запись, потом отправка, и любая её неудача
(бот не настроен, сеть не ответила, телеграм отказал) уходит в лог с номером
заявки, а не наверх. Проверено на обоих отказах: отклонённое соединение
и ответ `401` от `api.telegram.org`.

Токен и chat_id — только из окружения, в коде их нет:
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. Читаются через `os.environ` в момент
отправки; `.env` подхватывается при старте и в репозиторий не входит —
см. `.env.example`.

### Защита от роботов

Без капчи, двумя проверками:

- **скрытое поле-ловушка** — человек его не видит и не заполняет. Заполнено —
  заявка не сохраняется, а бот получает ту же страницу «спасибо»;
- **метка времени показа формы** — скрытое поле, подписанное HMAC на сервере.
  Отправлено раньше трёх секунд после загрузки, подпись не сходится или метке
  больше суток — форма возвращается **с уже написанным текстом** и просьбой
  отправить ещё раз. Ни одно слово человека при этом не теряется.

Подпись обязательна: без неё бот просто поставит в поле нужное число. Секрет —
`FORM_SECRET`; не задан — берётся случайный на время работы процесса.

Пустые поля возвращают страницу с сообщением из контента и кодом 422.

## Шрифты

Лежат в `static/fonts/` как woff2, подключены через `@font-face` в `input.css`:
ни одного обращения к внешнему домену. Вариативные — один файл на подмножество
(cyrillic, latin) закрывает весь диапазон начертаний. Все три под лицензией
SIL Open Font License 1.1.
